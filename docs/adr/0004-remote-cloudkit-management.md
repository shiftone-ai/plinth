# ADR 0004: iCloud を使った別端末の管理

## 決定

Plinth の Mac・iPad・iPhone アプリに「この端末」と「ほかの端末」を設ける．端末の発見には，設定集とは別の CloudKit private database のゾーンを使う．端末が遠隔管理を有効にしたときだけ，名前，OSの種別，更新時刻，公開鍵を載せる．展示設定と管理者資格情報は発見用レコードに載せない．端末一覧から隠す操作は操作側の端末だけに保存し，展示端末の有効状態を変えない．

同じ Apple Account は端末を探すための条件であり，操作の許可には使わない．展示端末で管理者が遠隔管理を有効にし，8桁の登録コードを表示する．操作側がコードを入力した後，展示端末の管理者が対象名を見て承認する．コードは5分，登録要求は2分で失効し，誤入力は5回までとする．承認は端末ごとの公開鍵と Apple Account に結び付け，展示端末から解除できる．Apple Account が変わると承認を失効させる．秘密鍵は端末の Keychain に保存し，他の端末へ同期しない．

操作要求と結果は有効期限付きの別レコードで送る．送信側は相手の鍵宛に内容を暗号化し，ヘッダーと暗号文に署名する．CloudKit の `encryptedValues` に入れる内容も，アプリ内で暗号化した状態とする．展示端末は署名，承認，宛先，Apple Account，期限を確認し，要求 ID を端末内に保存してから処理する．結果が届くまで，操作側は CloudKit への送信成功を端末での処理成功と表示しない．期限内に結果を確認できない場合は「結果不明」とする．

状態応答には，展示状態，保存済み Profile とその revision，展示中の revision，現在の画面構成を含める．操作側はこの設定から開始 URL，閲覧先，入力，無操作復帰，展示先と出力を編集する．保存前に対象名と変更点を示す．展示端末の Root は現在の revision，端末上の未保存 draft，Profile の妥当性と利用可能な出力を調べ直し，既存の Profile 保存経路で変更項目だけを保存する．保存しても展示中の `activeProfile` とページは切り替えない．

展示の開始，やり直し，停止，再開は展示端末の Root の既存の状態遷移へ渡す．やり直しと停止は操作側で対象名を確認してから送る．結果は状態遷移が完了してから返す．iPad・iPhone が背景にある間は要求を処理しない．別端末の管理から管理者画面や認証画面へ進む操作は設けない．

## 理由

CloudKit private database だけで操作を許すと，同じ Apple Account を使うすべての端末が展示を変更できる．展示端末での個別承認と鍵の照合により，利用者が選んだ端末だけに権限を渡す．要求 ID を先に保存すると，再送された要求で展示操作や設定保存を繰り返すことを防げる．

設定の保存と展示への反映を分けるのは，来場者のページを編集中に切り替えないためである．画面と解像度は操作側の端末ではなく展示端末の現在の接続状態で判定する．ネットワーク越しの結果を待つ間に状態が変わり得るため，操作側での選択肢表示だけでは保存可否を決めない．

## 責務と確認範囲

Root は承認，要求の状態，Profile の保存，展示の遷移を裁定する．Administration は端末上の draft を所有する．Presenter は端末一覧と結果を表示用の値へ変換する．CloudKit，暗号化，Keychain は Adapter が扱う．ブラウザからの管理は [ADR 0003](0003-web-administration.md) の端末内 HTTP サーバーを使い，この通信経路とは独立している．

2台の `RootRuntime` による状態取得，設定保存，展示操作の試験と，隔離した Simulator の SwiftUI 画面操作を実行した．実 CloudKit での2台間の往復，実機の出力切断，異なるネットワークでの展示操作は未確認である．
