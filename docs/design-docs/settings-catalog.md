# 設定集

[Issue #36](https://github.com/shiftone-ai/plinth/issues/36) の実装境界を示す．

設定集は端末の `savedProfile`，編集中の `draftProfile`，展示中の `activeProfile` とは別に保存する．登録と項目の更新には保存済みの設定を使い，編集中の設定は使わない．項目を開くと内容と現在の設定との差を表示し，「エディタに読み込む」で draft に入れる．端末の保存操作が成功するまで savedProfile は変わらず，展示中の activeProfile はそのまま保つ．資格情報，Web管理の有効状態，Webセッション，表示言語は項目に含めない．

Root Mediator は項目の登録，表示，削除，共有，競合と非同期結果を裁定する．Administration Mediator は登録元の保存済み設定，選択した項目の draft への読み込み，合言葉の一時保持を扱う．Presenter が状態を表示へ投影し，View は意図を送る．`CatalogRepository` は端末内の設定集を原子的に保存し，`CatalogCloudSync` と `EncryptedCatalogFile` は Root が選んだ Effect だけを実行する．

項目の詳細を開いた後に内容が更新された場合，適用時には Root が最新の項目を引き直す．別端末の画面や解像度が使えない場合は出力先に注意を表示し，利用可能な値を選ぶまで端末への保存を受け付けない．

iCloud 同期は端末ごとに有効化する．有効化だけでは端末内の項目を共有しない．共有する項目は管理者が確認して選び，CloudKit private database の `iCloud.ai.shiftone.plinth` に保存する．名前と設定本体は CKRecord の `encryptedValues` に入れる．CKSyncEngine の状態，record change tag，受信済みの版と削除情報は端末内に保存し，端末内の設定集への保存が失敗した後も次の起動で受信内容を再送する．受信項目は初め非表示とし，表示と展示への適用は端末ごとに選ぶ．共有項目の更新と削除は確認後に送信し，送信待ちの削除は保存して競合時に管理者の選択を待つ．Apple Account が変わると同期を止め，旧アカウントの項目を新アカウントへ送らない．

同期処理にはセッション識別子を付ける．アカウント照会の途中で同期を止めた場合は古い開始・送信処理を破棄し，古いセッションから届いた通知は Root が拒否する．競合中の項目は変更点を表示し，管理者が版を選ぶまで編集・送信を保留する．

書き出しは項目を版付きの JSON にした後，PBKDF2-HMAC-SHA256（salt 32 バイト，60 万回）で導出した鍵を使い，AES-256-GCM で暗号化する．ヘッダーの形式版と導出回数も認証対象にする．読み込みは OS のファイル選択画面と協調アクセスを使い，形式とサイズ，項目の値を確認してから設定集への追加候補を表示する．読み込みだけで共有や展示の設定は変えない．

CloudKit container の有効化，配布用の署名プロファイル，production schema の反映と実サービス間の送受信は，配布前にその環境で確認する．
