# 設定集

[Issue #36](https://github.com/shiftone-ai/plinth/issues/36) の実装境界を示す．

設定集は端末の `savedProfile`，編集中の `draftProfile`，展示中の `activeProfile` とは別に保存する．登録と項目の更新には保存済みの設定を使い，編集中の設定は使わない．項目を開くと内容と現在の設定との差を表示し，「エディタに読み込む」で draft に入れる．端末の保存操作が成功するまで savedProfile は変わらず，展示中の activeProfile はそのまま保つ．資格情報，Web管理の有効状態，Webセッション，表示言語は項目に含めない．

Root Mediator は項目の登録，表示，削除，共有，競合と非同期結果を裁定する．Administration Mediator は登録元の保存済み設定，選択した項目の draft への読み込み，合言葉の一時保持を扱う．Presenter が状態を表示へ投影し，View は意図を送る．`CatalogRepository` は端末内の設定集を原子的に保存し，`CatalogCloudSync` と `EncryptedCatalogFile` は Root が選んだ Effect だけを実行する．

保存済み設定の読み込みに失敗した端末は SafeHold に留まる．既存の管理者認証を通して設定集を読み込み，保存を確定した場合に限り，`ProfileRepository` は壊れた設定ファイルを端末内に別名で保管してから，新しい設定へ原子的に置き換える．通常の保存は壊れたファイルを上書きしない．

端末内の設定集が壊れている場合，管理画面で明示的に復旧を確定すると，`CatalogRepository` は元のファイルを別名で保管して空の設定集を開く．その後，暗号化バックアップを読み込むか，iCloud 同期を再設定できる．読み込み失敗が一時的な入出力エラーの場合は復旧操作を表示しない．

項目の詳細を開いた後に内容が更新された場合，適用時には Root が最新の項目を引き直す．設定集の保存中は項目を読み込まない．暗号化ファイルの読み込みと書き出しは，一方の処理や確認画面が終わるまで他方を開始しない．展示を始めると進行中のファイル操作を取り消し，管理画面に残った読み込み候補や書き出し結果を消す．端末固有の Web 管理の有効状態は読み込み前の設定から引き継ぐ．別端末の画面や解像度が使えない場合は出力先に注意を表示し，利用可能な値を選ぶまで端末への保存を受け付けない．表示先が保存前に切断された場合も，保存時に再確認する．

iCloud 同期は端末ごとに有効化する．有効化だけでは端末内の項目を共有しない．共有する項目は管理者が確認して選び，CloudKit private database の `iCloud.ai.shiftone.plinth` に保存する．名前と設定本体は CKRecord の `encryptedValues` に入れる．CKSyncEngine の状態，record change tag，受信済みの版と削除情報は端末内に保存し，端末内の設定集への保存が失敗した後も次の起動で受信内容を再送する．受信項目は初め非表示とし，表示と展示への適用は端末ごとに選ぶ．共有項目の更新と削除は確認後に送信し，送信待ちの削除は保存して競合時に管理者の選択を待つ．Apple Account が変わると同期を止め，旧アカウントの項目を新アカウントへ送らない．異なるアカウントに同じ項目 ID があっても，各アカウントの項目を端末内に別々に保持し，現在のアカウントの項目だけを表示・変更する．

同期処理にはセッション識別子を付ける．iPad では画面の接続前に端末内の設定集を読み込み，同期が有効なら CKSyncEngine を起動する．画面がすべて切断されてもアプリの同期処理は保持する．アカウント照会中に設定集の保存が始まった場合は，保存の終了後にアカウントを再照会する．古いセッションから届いた通知は Root が拒否する．サインインが必要だった場合は，サインイン後に管理画面から再照会できる．アカウント情報を一時的に取得できない場合は端末内の項目と送信待ちの変更を保ち，通知または管理画面の再試行から同期を再開する．オフライン表示から再試行するときは，残っている同期セッションを止めてからアカウントを照会する．共有の確定には現在の Apple Account で稼働中の同期セッションを要する．CloudKit のゾーンが削除された場合はゾーンを作り直し，端末に残る共有項目を再送する．競合していた項目は管理者が選んだ内容を再送する．同じ ID の端末内項目と受信項目が衝突した場合も選択でき，端末内版を選ぶとその版を iCloud へ共有する．送信の一部だけが成功しても同期完了とは表示しない．端末内の同期状態ファイルが読めない場合は別名で保管し，新しい状態で受信をやり直す．競合中の項目は変更点を表示し，管理者が版を選ぶまで編集・送信を保留する．別の Apple Account の競合は，そのアカウントに戻るまで解決できず，新しいアカウントの同期状態には持ち込まない．アカウント変更で利用できなくなった項目は詳細から閉じ，変更や削除を受け付けない．確認中だった変更と削除も取り消す．

CloudKit の受信通知と端末内の保存完了が重なった場合は，同じ項目の送信を保留して受信内容を設定集へ反映する．保存が失敗した場合も，待機中の受信内容を元の設定集に対して再保存する．続けて失敗した場合は再試行まで保持する．競合の解決中に同じ項目を再受信した場合は，解決済みとして送らない．受信結果の通知より先に保存が完了する場合も，Adapter が受信済みの版を確認して古い内容で上書きしない．同期開始中の変更は開始後に送信し，古い送信コマンドでも別の項目への変更は保持する．削除の送信前には取得済みの版を照合し，iCloud 側で更新されていれば競合として保留する．

古い設定集ファイルの削除競合にアカウント識別子がない場合は，その時点で保存されていた共有項目または送信待ちの削除から所属アカウントを判定する．

通常の Mac 開発用ビルドには CloudKit 権限がないため，管理画面で同期を有効化できない．App Store 用と Developer ID 用の署名ビルドでは対応する権限を付ける．

iCloud へ送る暗号化データは，項目ごとに 900,000 バイト以下とする．共有や共有項目の変更でこの上限を超える場合は，端末内の項目を共有済みに変更せず，管理画面に理由を示す．設定集の保存中は書き出しを開始しない．

書き出しは項目を版付きの JSON にした後，PBKDF2-HMAC-SHA256（salt 32 バイト，60 万回）で導出した鍵を使い，AES-256-GCM で暗号化する．ヘッダーの形式版と導出回数も認証対象にする．読み込みは OS のファイル選択画面と協調アクセスを使い，形式とサイズ，項目の値を確認してから設定集への追加候補を表示する．以前の Apple Account にしか属さない同一項目が残っていても，利用できる端末内の別項目として追加する．読み込みだけで共有や展示の設定は変えない．

CloudKit container の有効化，配布用の署名プロファイル，production schema の反映と実サービス間の送受信は，配布前にその環境で確認する．
