# Macの展示出力

Mac専用版では出力方式と出力先を分ける．元の設計書v0.2の1画面条件を，この追加要件で拡張する．iPad版をMac上で動かす方式とは区別する．

| 方式 | 出力先 | 展示中のウィンドウ |
| --- | --- | --- |
| 全画面固定（既定） | 自動，または接続中の画面を指定 | 枠を消して固定し，ほかの画面を黒く覆う |
| ウィンドウ表示 | 操作者が移動して決める | 移動・拡大縮小を許可する |

自動では外部画面を優先し，なければ主画面を使う．指定した画面がなくなった場合，別の画面へ自動で移さず停止する．画面IDはOSが割り当てるため，再起動などでIDが変わった場合は再選択する．ウィンドウ表示では画面の指定を開始条件にしない．

Viewは設定のPropsを描画し，型付きの編集意図を送る．Rootは画面のFactと保存した設定から出力先・方式を決め，PresentationRequest付きEffectを発行する．AppKit Adapterは選ばれた画面へ配置し，固定表示ではRoot配下で遮蔽ウィンドウを所有する．解除・停止・終了時にすべて解放し，元のウィンドウ状態とOS Presentationを戻す．

全画面固定ではAppKitでカーソル位置を監視し，選んだ画面の外ならFactをRootへ送る．Rootが補正を選び，公開のCoreGraphics APIで位置を戻す．ウィンドウ表示と管理中は補正しない．ネイティブのWeb入力を保つ．管理画面へ戻る時と終了時に監視を解放する．補正に失敗したら展示を停止する．macOS 27.0.1の専用Mac（1920×1080の1画面）で，画面内の試験領域からカーソルが出ないことと，解除後に自由に動くことを実際の座標で確認した．ウィンドウ表示では枠とカーソルの自由が保たれ，通常の全画面固定でも展示・5秒復帰・認証・画面復元が成功した．複数の実ディスプレイは未確認．

OS Presentationの切り替えでも画面変更通知が届くため，画面ID・位置・解像度が同じ通知では展示を継続する．展示中や展示へ戻れる解除中に位置や解像度が変わった場合は停止する．停止後の管理者解除は，画面構成の変化で取り消さない．

Mac専用のStore版はiPad版と同じサービス名・Data Protection Keychain・access groupを使い，既存設定の管理者パスワードを参照する．最初のMac版が使った別サービスは読み取りで引き継ぎ，新しい設定や資格情報を優先する．[AppleのKeychain実装の説明](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains)

## 縦置き

macOSで回転を設定した画面では，OSが報告する画面領域を全画面固定の出力先に使う．横向きの寸法には固定しない．回転は展示開始前に設定する．展示中に画面領域が変わった場合は，上記の画面変更と同じく停止する．

1080×1920の縦置きで，Webの表示領域，四隅までの描画，マウスの位置と画面外への移動制限，解除後の復元を実機で確認する．現時点では縦向きの実機試験は未実施．
