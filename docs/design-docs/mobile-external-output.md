# iPhone・iPadの外部表示

外部表示専用Sceneに実際のWKWebViewを置き，外部画面の幅と高さに合わせてWebページを描画する．本体のミラーリングやWebの画像コピーによる映像出力は使わない．

## Sceneと所有

iOS 27では本体のViewControllerに `UISceneAccessory.externalNonInteractive` を登録する．18.4〜26ではScene Manifestの外部表示用設定を使う．登録，Window，ViewControllerとWebKit AdapterはMobileSessionがRoot配下で所有し，Scene切断とstopで破棄する．外部表示の初期値はOSが選んだ出力モードとし，対応する解像度から選んだ値をProfileへ保存できる．画面全体を縮小するoverscan補正を無効にする．補正設定の元の値をScene所有者が保持し，切断とstopで戻す．

外部用の `.windowExternalDisplayNonInteractive` と，操作可能な `.windowApplication` を区別する．後者の追加ウィンドウは対応する端末でのみ準備できる．外部表示専用Sceneの接続には複数ウィンドウの対応を要求しない．外部Sceneが接続済みの場合は「展示ウィンドウを開く」を表示しない．複数ウィンドウの対応だけでは追加を許可せず，Rootの共通判定で表示と要求の受付をそろえる．

外部の接続，対応モードと全画面の準備完了は型付きFactでRootへ送る．管理画面からの開始は接続と選択モードを検証する．起動時は保存した出力先の準備を待つ．切断時は停止し，本体へ展示を移さない．停止後に管理者解除を始めた場合は，再接続の通知で認証を取り消さない．展示中からの解除で外部画面が失われた場合は，認証を取り消して停止する．再接続だけでは展示を自動再開しない．

## 解像度の選択

表示専用の外部画面では，「自動」と `UIScreen.availableModes` の候補を設定画面へ出す．初期値の「自動」はOSの選択を維持する．明示した解像度とピクセルの縦横比をProfileへ保存し，開始時とアプリの再起動後に適用する．対応していないモードでは開始しない．製品名や一律の1080pから物理解像度を推測しない．

Viewは選択Intentだけを送る．RootがPresentation要求を選び，Runtimeの所有するoperationがUIKitの準備を待つ．モードはWindowへの画面の割り当て前に設定する．OSがSceneを入れ替える場合は，準備中の同じoperationで新しいSceneを受け取り，古いSceneへの参照を解放する．

入力機器の検出直後にも外部Sceneが入れ替わったため，Scene・画面・描画領域・出力モードが0.5秒間変わらず，前面かつ全画面であることを確認して準備を完了する．本体は操作可能な前面状態を要求する．表示専用の外部Sceneでは，前面で入力を受けない `foregroundInactive` も表示可能な状態として扱う．実機の再開時にはこの状態になり，入力用Sceneと同じ判定では10秒の準備期限に達していた．待機TimerはAdapterが所有し，変更・切断・取消時は世代を無効にしてから破棄する．準備全体は10秒で失敗し，取消後の成功は採用しない．展示開始後の切断は停止し，再接続だけで再開しない．

`nativeBounds` と描画倍率は取得できるが，今回の接続ではパネルの物理解像度を特定できていない．取得値とEDIDに関する未確認事項は [API調査](../references/ipad-external-display.md#解像度と画面倍率) を参照する．

## 縦置き

外部出力に0度・右90度・180度・左90度の回転設定を設け，Profileへ保存する．初期値は0度．出力モードと回転を別の値とし，1920×1080の出力を90度回転する場合は，Webを1080×1920の領域で再レイアウトする．本体の向きには連動させない．

Apple公式資料，既存アプリの前例と最小アプリの結果は [回転の調査](../references/external-display-rotation-precedents.md) に記録する．iPadOS 26.4と27のSimulatorでは，表示専用Sceneへの向き変更要求がエラー101で拒否されたため，SwiftUIの標準APIで描画する方式を採用した．90度・270度では幅と高さを入れ替え，Webとカーソルを同じ領域で回転する．

Rootが保存した向きをPresentationRequestとPropsへ渡す．MobileのPresentation AdapterはWebと相対マウス入力に同じ論理寸法を提供し，全画面の成立は回転前のSceneで判定する．Viewは寸法と向きを描画へ反映するだけで，読み込みや保存を起動しない．本体表示とMacのPresentation要求には回転を適用しない．

iOS 26以降では，WebKit AdapterがWKWebViewの4辺のスクロール端効果を非表示にする．展示にはネイティブのバーを置かず，端までWebを描画するためである．iPadOS 27の最小実験では，この効果を残すと回転した外部画面の端がぼけた．

iPadOS 26.4と27のSimulatorで，全4方向のWeb表示領域，クリック，ドラッグ，hover，スクロール，保存後の再起動，解除取消と，90度のインライン動画再生を確認した．スクロール端効果によるぼけの修正は，外部画面の画素検査と目視で再確認した．iPadOS 26.6.2の実機では1920×1200の外部モードで全4方向の操作・再起動・解除取消が成功し，ユーザーが実パネルの正円と黒帯なしを確認した．通常起動した展示サイトも「解像度：自動・右90度」で文字の潰れと黒帯がないことを確認した．物理入力によるWeb操作と縦置きでの動画の全画面表示は未確認．

## 本体操作

外部表示専用Sceneでは，本体を操作面と管理者入口に使う．マウスの位置・押下・解放，長押しによるドラッグ，スワイプとマウスのスクロールを外部Webの座標へ変換して送る．外部には描画したカーソルを出す．

操作は型付きIntentから同期CoRでRoot Mediatorへ送る．Rootは展示状態，出力方式，Web世代，操作の許可を判定し，Effectを選ぶ．実行直前にもWebKit AdapterからRootへ許可を照会し，解除後や旧世代への遅延入力を拒否する．

Web操作には標準DOM APIを使い，URL制限は通常と同じWKNavigationDelegateを通る．押下・移動・解放，Pointer Capture，HTMLのドラッグ＆ドロップとキャンセルを扱う．読み取り可能なスタイルシートのhoverを操作位置に反映する．クロスオリジンのスタイルシートや，信頼されたDOMイベントだけを受け付けるページでの同等性は保証しない．

DOMイベントのisTrustedはfalseだが，公開のWebKit JavaScript実行APIはユーザー操作状態を伴う．Macの実WebKitでクリック時のnavigator.userActivation.isActiveを確認し，iPad Simulatorでは無音のAudioContextがrunningへ移ることを確認した．スピーカーからの音は未確認．ファイル選択など，明示的に禁止するWeb機能は引き続き拒否する．

入力の実行は順に行い，連続した移動とスクロールをまとめる．未処理入力の上限を設け，処理できない場合はFactをRootへ送り，展示を停止する．Web世代の変更で待ち入力を破棄する．

スクロールは，タッチ・トラックパッド・マウスともUIKitのPan Gestureから受け取る．移動量の1ポイントを1 CSSピクセルとして送り，外部画面や本体の高さでは倍率を変えない．GameControllerではスクロールを購読しない．実機のロック中にも両APIから同じ操作が届いたためである．保留中のスクロールは符号と小数部分を保って加算し，カーソル位置の0〜1の範囲へ制限しない．WebKitではカーソル位置のスクロール領域を優先し，該当する領域がなければページ全体を動かす．

操作可能な外部ウィンドウでは，従来どおりWKWebViewへネイティブ入力を渡す．表示専用Sceneのマウス移動とボタンは，UIKitのPointer LockとGameControllerの相対入力を使う．Rootが取得を裁定し，取得できない場合や失った場合は停止する．解除・切断・終了時に解放する．マウス切断やドラッグ取消では，Webの押下状態も取り消す．取得完了後にSceneとロック状態を再確認し，認証取消後は復帰ページの準備完了を待って再取得する．

### マウス固定の設定案内

Rootはロックの取得失敗・喪失を状態に記録し，Presenterが停止中の案内表示へ投影する．Passive Viewは本体に「マウスを固定できません」と復帰手順を表示する．iPadOS 26以降では「設定」の「マルチタスクとジェスチャ」にある「フルスクリーンアプリ」を案内する．この設定のほかに全画面へ切り替える操作や，バックグラウンドのアプリを終了する操作は求めない．ほかの環境では全画面表示を案内する．

iPad・iPhoneで展示中にアプリを一時的に離れた場合は，Rootが再開待ちを記録する．本体が前面へ戻ると，旧Webの停止完了を待って保存済みProfileで展示を作り直し，必要なマウス固定を再取得する．非アクティブ化の重複通知では再開待ちを失わない．管理者解除を始めた場合，OSからスリープ通知を受けた場合や画面の切断があった場合は再開待ちを破棄する．OSのアプリ切替ジェスチャを防ぐ機能ではない．Macの非アクティブ化時の停止方針は変えない．

マウス固定の失敗で停止した場合は，本体が前面へ戻ったFactで再確認する．Rootは旧Webの停止完了を待ち，元のProfileで画面準備とロック取得をやり直す．前面を再び離れた場合や認証を始めた場合は，この再確認を取り消す．管理者の停止・解除中，スリープ通知，外部画面の切断やエラーによる停止では自動再開しない．再取得時も元のスリープ設定を上書きせず，最終的な解除時に復元する．新しい展示開始・ロック取得要求では失敗の記録を消す．外部には案内や管理画面を表示しない．

検出対象は `pointerLockState.isLocked` による取得結果であり，OSのマルチタスク設定そのものではない．本体Sceneが画面と同じ寸法でもロックが拒否されたため，寸法から「フルスクリーンアプリ」が選択済みと推測しない．設定の条件と実機結果は [ポインタの調査](../references/ipad-external-display.md#ポインタを展示画面へ固定する候補) を参照する．

## 管理と認証

外部用Viewは展示中だけWebを表示する．解除中，管理中，停止中は黒くし，管理画面やパスコードを外部へ出さない．解除の取消と再開始でも保存した展示先を維持する．

## 検証

iOS 27のiPad Simulatorで，720×480の外部Web，本体の管理者入口，解除取消と再開始の通しUI試験が成功した．本体は820×1180であり，外部Sceneと表示領域を分けている．iOS 27のiPhone Simulatorでも同じ通しUI試験が成功し，1920×1080の外部出力設定でも再確認した．本体の1指スワイプで実際のscrollYが変わり，ページ下部が表示領域へ入ることも確認した．iPadとiPhoneの1920×1080外部Sceneで，音声なしのインライン動画，切断時の停止，管理者解除，再接続後の動画再開も確認した．iPadOS 26.6.2の実機でも，外部表示・許可／禁止リンク・スクロール・ドラッグ・無音の再生許可・動画・解除と再開が成功した．物理入力によるWeb操作，切断と再接続，長時間運用，スピーカーからの音は未確認．

iPadOS 26.6.2の実機では，USBハブ経由のトラックパッドを接続し，「ウインドウ表示アプリ」でのロック拒否と案内表示を再現した．「フルスクリーンアプリ」へ変更後，通常設定で3回の再起動が成功し，外部画面にカーソルが描画されていることを取得画像で確認した．最小アプリでは実際の移動・スクロール入力とロック成立も確認した．修正後のPlinthでの物理入力によるWeb操作と画面の端での制限は，取得画像や本体のタッチ試験だけでは確認済みとしない．

接続契約は [Appleの外部表示資料](https://developer.apple.com/documentation/uikit/presenting-content-on-a-connected-display) と，インストール済みXcode 27のUIKit公開ヘッダーで確認した．

## 反復運転の検証

専用Macの実WebKit・Native Effect Executorで，120秒ずつ時計を進めて1週間分の5,040回の無操作復帰を実行した．最新版の再試験では252.6秒で完了し，旧Viewの取り外し，表示用Viewが1つであること，処理中のTaskと記録数が上限内であることを確認した．これは実時間での1週間運転や展示用iPadの実機試験とは区別する．

旧OSのSimulatorでは，UIKitが報告する外部モードは720×480だった．Framebufferだけを1920×1080へ変えると左上だけに描かれるため，旧OSの試験は報告されたモードに合わせる．720×480で独立表示，クリック・スクロール，ドラッグ，無音音源の再生許可，解除，切断・再接続後の動画を確認した．動画が画面の一部へ閉じ込められないことも画像で確認した．iPadOS 26.6.2の実機と試験に使った外部ディスプレイでは，CoreDeviceの `nativeSize` が1920×1080，UIKitの描画領域が1920×1200だった．この差から物理解像度を確定しない．1080pでは黒帯が消えても円が歪み，最小UIKitアプリを1920×1200で再描画すると正円かつ黒帯なしになった．EDID自体の解析は未実施である．APIの契約と比較用Viewの再描画については [縦横比の調査](../references/mobile-output-aspect-ratio.md) を参照する．
